- **浅拷贝（Shallow Copy）**：只复制“表面”，**复制指针地址，不复制指针指向的内容**。结果是新旧两个对象**共享同一份内存资源**。

  - **浅拷贝 = 发送文件的“快捷方式”** 你把电脑里文件的“快捷方式”发送给朋友。快捷方式虽然有两个，但指向的磁盘文件只有一份。

    - **后果1**：朋友在快捷方式里修改了文件，你的文件内容也变了。
    - **后果2**：如果你把原文件删了，朋友的快捷方式就会报“找不到文件”错误（相当于 C++ 中的**野指针 / 悬空指针**）。

    

- **深拷贝（Deep Copy）**：彻底复制“内部”，**在堆上申请全新的内存，并把内容完整复制过去**。结果是新旧两个对象**各自拥有独立的内存资源**。

  - **深拷贝 = 发送文件的“另存为副本”** 你把文件“复制-粘贴”一份给朋友。现在磁盘上有两份完全独立的文件。
    - **结果**：朋友随意修改或删除他的文件，对你的文件没有任何影响。







# 代码实例

```cpp
#include<iostream>
#include<string.h>

class String
{
private:
	char* m_Buffer;
	unsigned int m_Size;
public:
	String(const char* string) //构造函数,string是一个字符串
	{
		m_Size = strlen(string);
		m_Buffer = new char[m_Size + 1];
		memcpy(m_Buffer, string, m_Size);
		m_Buffer[m_Size] = 0;
	}

	String(const String& other)
		:m_Size(other.m_Size)
	{
		m_Buffer = new char[m_Size + 1];
		memcpy(m_Buffer, other.m_Buffer, m_Size + 1);
	}

	~String()
	{
		delete[] m_Buffer;
	}

	char& operator[](unsigned int index)
	{
		return m_Buffer[index];
	}

	friend std::ostream& operator<<(std::ostream& stream, const String& string);
};

std::ostream& operator<<(std::ostream& stream, const String& string)
{
	stream << string.m_Buffer;
	return stream;
}

int main()
{
	String string = "QJY";
	String Second = string;

	Second[0] = 'T';

	std::cout << string << std::endl;
	std::cout << Second << std::endl;

	std::cin.get();
}
```



---

## 1. 运行结果预测

运行这段代码，控制台的输出为：
```text
QJY
TJY
```
**分析：** 修改 `Second[0] = 'T'` 后，`string` 的内容依然是 `"QJY"`，没有受到任何影响。这证明 `Second` 和 `string` 拥有**互相独立、互不干扰的内存空间**。

---

## 2. 深拷贝的实现细节

在你的代码中，深拷贝是由自定义的 **拷贝构造函数** 实现的：

```cpp
String(const String& other)
    : m_Size(other.m_Size)
{
    // 1. 重新在堆内存（Heap）中申请一块全新的内存空间
    m_Buffer = new char[m_Size + 1]; 
    
    // 2. 将源对象（other）内存中的数据完整复制到新的内存空间中
    memcpy(m_Buffer, other.m_Buffer, m_Size + 1); 
}
```

当执行 `String Second = string;` 时：
1. 触发拷贝构造函数 `String(const String& other)`。
2. `string.m_Buffer` 指向堆内存块 A（保存 `"QJY"`）。
3. `Second.m_Buffer` 申请了全新的堆内存块 B（同样保存 `"QJY"`）。
4. 内存结构如下：
   ```text
   string.m_Buffer  ---> [ 'Q', 'J', 'Y', '\0' ] （内存块 A）
   Second.m_Buffer  ---> [ 'Q', 'J', 'Y', '\0' ] （内存块 B）
   ```
5. 当执行 `Second[0] = 'T'` 时，修改的是内存块 B，内存块 A 完好无损。
6. 函数结束析构时，`string` 释放内存块 A，`Second` 释放内存块 B，**程序安全退出**。

---

## 3. 如果是“浅拷贝”会发生什么？

如果你**删除/注释掉**自定义的 `String(const String& other)` 拷贝构造函数：

编译器会自动生成默认的拷贝构造函数，执行**值拷贝（按位复制）**：
```cpp
// 编译器默认生成的浅拷贝行为逻辑等价于：
Second.m_Buffer = string.m_Buffer;
Second.m_Size = string.m_Size;
```

**浅拷贝的后果：**
1. **数据污染：** `Second.m_Buffer` 和 `string.m_Buffer` 会指向**同一块内存地址**（内存块 A）。
   ```text
   string.m_Buffer  ---\
                        +---> [ 'Q', 'J', 'Y', '\0' ] （内存块 A）
   Second.m_Buffer  ---/
   ```
2. **连锁修改：** 执行 `Second[0] = 'T'` 后，`std::cout << string` 也会输出 `"TJY"`。
3. **Double Free 崩溃（致命错误）：** 程序退出 `main()` 函数时，`Second` 和 `string` 的析构函数都会被调用：
   - `Second` 先析构，执行 `delete[] m_Buffer;`（内存块 A 被销毁）。
   - `string` 后析构，再次执行 `delete[] m_Buffer;`（试图销毁已经被释放的内存块 A）。
   - **程序直接崩溃（报错：Double Free / Corruption）**。

## 4. 补充建议：防止拷贝赋值运算符的漏洞（Rule of Three）

虽然你写好了**拷贝构造函数**（适用于对象初始化 `String Second = string;`），但如果有人在代码里写：

```cpp
String string = "QJY";
String Second = "ABC";

Second = string; // ⚠️ 注意：这是“赋值”，不是“初始化”！
```

此时不会调用拷贝构造函数，而是调用编译器默认生成的 **拷贝赋值运算符 `operator=`**，这又会导致**浅拷贝和内存泄漏**！

为了完美的深拷贝，建议补充 **拷贝赋值运算符**：

```cpp
String& operator=(const String& other)
{
    if (this != &other) // 1. 防止自我赋值 (e.g. string = string)
    {
        delete[] m_Buffer; // 2. 释放当前对象旧的内存空间
        
        m_Size = other.m_Size;
        m_Buffer = new char[m_Size + 1]; // 3. 申请新内存
        memcpy(m_Buffer, other.m_Buffer, m_Size + 1); // 4. 复制数据
    }
    return *this; // 5. 返回引用以支持链式赋值 (a = b = c)
}
```
