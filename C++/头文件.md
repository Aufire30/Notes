# 头文件保护符

> 防止头文件被重复 `#include` 导致编译报错

## #pragma once

> 现代方式

```cpp
// Log.h
#pragma once

void Log(const char* message);
```

直接向编译器发指令，告诉编译器：“**在当前编译过程中，这个物理文件只读取并解析一次**”。

> [!CAUTION]
>
> #### `#pragma once` 的坑：软链接/拷贝路径识别（极少见）
>
> 如果同一个物理头文件在磁盘上通过“软链接（Symlink）”或复杂的虚拟路径被引用，极个别老旧编译器可能会误以为它们是“两个不同的文件”，从而包含两次。



## #ifndef

> 传统方式

```cpp
// Log.h
#ifndef LOG_H
#define LOG_H

void Log(const char* message);

#endif // LOG_H
```

第一次包含时定义 `LOG_H` 宏；第二次再包含时，`#ifndef LOG_H` 为假，直接跳过整个头文件内容。

> [!CAUTION]
>
> #### `#ifndef` 的坑：宏名冲突
>
> 假设你有两个不同文件夹下的头文件都叫 `Log.h`：
>
> - `Engine/Log.h` 定义了 `#define LOG_H`
> - `UI/Log.h` 也定义了 `#define LOG_H`
>
> 当项目同时引用它们时，第二个文件就会被误认为“已经包含过了”而被直接忽略，抛出极其诡异的**类型或函数未定义错误**。

# include后引号和尖括号的区别

## 双引号

#### `#include "Log.h"`

- 搜索顺序：
  1. **优先搜索当前源文件所在的本地目录**（即你项目里的代码文件夹）。
  2. 如果在当前目录没找到，再去编译器设置的项目头文件路径、系统标准库路径中查找。
- **主要用途**：用来引入**你自己写的头文件**或项目内部的 `.h` 文件。

> 即**相对路径**

## 尖括号

#### `#include <iostream>`

- 搜索顺序：
  1. **直接跳过当前本地目录**。
  2. 直接去**系统标准库目录**、操作系统 SDK 路径以及编译器全局配置的第三方库路径中查找。
- **主要用途**：用来引入 **C++ 标准库**（如 `<iostream>`, `<vector>`, `<string>`）或第三方安装好的全局库。

> 即**绝对路径**
