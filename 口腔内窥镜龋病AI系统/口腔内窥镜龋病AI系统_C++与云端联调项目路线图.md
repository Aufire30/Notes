# 基于口腔内窥镜的实时口腔龋病AI系统：C++与云端联调项目开发路线图（全栈升级版）

这是一个结合了**软硬件交互、计算机视觉（CV）、医疗AI部署以及云端数字化病历管理**的全栈式硬核项目。为了保证临床诊断的**零延迟**，本路线图遵循工业级黄金法则：**使用 Python 训练 AI 模型，使用 C++ 进行端侧实时推理与高并发网络通信，后端服务进行数据持久化与病历检索**，真正打通“端-边-云”完整闭环。

---

## 📅 阶段一：筑基阶段（C++ 基础与工程规范）
**目标：** 掌握 C++ 核心语法与工程构建工具，学会像职业程序员一样配置和管理本地工程。

### 🛠️ 核心任务
1. **掌握 C++ 核心语法**：
   * 基础语法：变量、控制流、函数。
   * 核心重难点：**指针与引用**、内存管理（堆与栈）。
   * 面向对象编程（OOP）：类（Class）、继承、多态。
   * 现代 C++ 规范：智能指针（`std::unique_ptr` / `std::shared_ptr`）以避免内存泄漏。
   * 标准库（STL）：熟练使用 `std::vector`, `std::string`, `std::map` 等容器。
2. **熟悉工程与构建工具**：
   * 集成开发环境（IDE）：安装配置 **Visual Studio** (Windows) 或 **CLion**。
   * 构建工具：必须掌握 **CMake** 的基本语法，学会如何引入外部第三方库。

### 🎯 交付目标

* 能够**不参考教程**，独立使用 C++ 编写一个简单的“患者信息与病历管理命令行系统”。
* 理解 C++ 的内存分配原理，知道如何使用工具排查内存泄漏。

---

## 📅 阶段二：输入与脸面（OpenCV 视频流与 Qt 界面）
**目标：** 解决系统的“眼睛”和“外表”问题。口腔内窥镜本质上是一个支持标准 UVC 协议的 USB 摄像头。

### 🛠️ 核心任务
1. **学习 OpenCV 图像处理库**：
   * 学会使用 `cv::VideoCapture` 驱动并读取内窥镜的实时视频流。
   * 掌握基本的图像预处理：图像裁剪（ROI）、亮度与对比度调整、双边滤波去噪。
2. **学习 Qt 框架（GUI 开发）**：
   * 学习使用 Qt Designer 设计直观的医疗软件界面。
   * 布局规划：主视窗（实时视频流显示）、控制面板（开始检测、暂停、拍照、**一键上传云端**按钮）、结果展示区（AI 诊断置信度、提示文本框）。
3. **软硬件打通（图像转换）**：
   * 编写转换逻辑，将 OpenCV 抓取到的视频帧（`cv::Mat` 格式）实时转换为 Qt 能够渲染的图像格式（`QImage` / `QPixmap`），并刷新到界面上。

### 🎯 交付目标
* 插上 USB 口腔内窥镜，运行 C++ 程序，能在 Qt 界面中看到流畅的实时口腔画面，点击“截图”按钮可将当前画面保存至本地。

---

## 📅 阶段三：大脑训练（AI 模型设计与 Python 借力）
**目标：** 准备系统的“核心大脑”。本阶段需要短暂切换至 Python 环境，高效完成模型训练与导出。

### 🛠️ 核心任务
1. **算法选型**：
   * 针对“实时性”要求，选择目标检测与分割领域的经典轻量化模型：**YOLOv8** 或 **YOLOv11**。
2. **数据准备与标注**：
   * 收集口腔龋齿（蛀牙）的图像数据（通过开源医学数据集获取，或自行采集）。
   * 使用 `Labelme` 或 `Roboflow` 工具对龋齿区域进行边界框标注。
3. **模型训练与导出（关键步）**：
   * 搭建 Python + PyTorch 环境，配置 YOLO 训练脚本，喂入标注好的口腔数据集进行训练。
   * 将训练好的 `.pt` 权重文件，通过导出脚本转换并输出为通用的 **ONNX (`.onnx`)** 格式。

### 🎯 交付目标
* 获得一个在验证集上精确率和召回率表现良好的 `caries_detector.onnx` 模型文件。

---

## 📅 阶段四：脑身结合（C++ AI 推理部署）
**目标：** 将训练好的 ONNX 模型无缝嵌入到 C++ 工程体中，实现本地 AI 解码与预测。

### 🛠️ 核心任务
1. **集成推理加速引擎**：
   * 在 C++ 工程中通过 CMake 引入 **ONNX Runtime** 或 **OpenVINO** 作为底层推理加速库。
2. **编写 C++ 推理管线（Pipeline）**：
   * **前处理**：将 OpenCV 获取的 `cv::Mat` 视频帧进行尺寸缩放（如 640x640）、通道转换（BGR 转 RGB）以及数据归一化。
   * **执行推理**：将处理后的张量（Tensor）送入推理引擎，执行前向计算。
   * **后处理**：解析模型输出的原始矩阵，提取出检测框的坐标和置信度，使用 **NMS（非极大值抑制）** 消除重复的框。
3. **动态可视化**：
   * 利用 OpenCV 将检测到的龋齿位置和概率实时绘制在视频帧上，并交由 Qt 渲染。

### 🎯 交付目标
* 内窥镜对准牙齿时，C++ 软件界面上的视频画面能自动、实时地用红框圈出“龋齿”位置，并打上类似 `Caries: 92%` 的标签。

---

## 📅 阶段五（新增）：云端筑巢（服务器端开发与数据设计）
**目标：** 搭建后端医疗病历服务器，提供标准的数据接收接口与存储能力，方便日后随时检索查找。

### 🛠️ 核心任务
1. **后端技术选型**：
   * 选择一门容易上手的后端语言（如 **Python FastAPI**、**Go Gin** 或 **Node.js**）搭建轻量级 HTTP 服务器。
2. **数据库设计（关系型数据库）**：
   * 使用 **SQLite**（开发阶段）或 **MySQL** 设计两张核心数据表：
     * **患者信息表（Patients）**：患者ID、姓名、性别、年龄、联系方式、录入时间。
     * **检查记录表（Records）**：记录ID、患者ID、本地AI诊断置信度、诊断文本结论、**云端图片存储路径（URL）**、检查时间。
3. **开发标准 API 接口**：
   * `POST /api/patient/add`：创建/录入新患者信息。
   * `POST /api/record/upload`：接收 C++ 客户端上传的结构化 JSON 数据以及**龋病诊断截图文件（Multipart Form Data）**。
   * `GET /api/records`：根据患者姓名或 ID 查询历史检查记录和图片。

### 🎯 交付目标
* 在本地或云服务器成功运行后端服务，能够通过 Postman 成功调用接口创建患者，并能成功上传一张图片保存到服务器指定的文件夹中。

---

## 📅 阶段六（新增）：端云联动（C++ 网络通信与异步数据上传）
**目标：** 让 C++ 客户端具备联网能力，在不影响本地实时看病（30 FPS）的前提下，将数据安全送上云端。

### 🛠️ 核心任务
1. **集成 C++ 网络通信库**：
   * 在 C++ 工程中引入 **nlohmann/json**（用于解析和构建 JSON 数据）以及 **CPR (C++ Requests)** 库（或使用 Qt 自带的 `QNetworkAccessManager`）来处理 HTTP 请求。
2. **数据序列化与打包**：
   * 当医生点击“保存并上传”时，C++ 客户端将当前患者ID、AI 诊断置信度等信息打包成 JSON。
   * 将含有红框的 `cv::Mat` 诊断截图编码为 JPG 二进制流，放入 HTTP Multipart 表单中。
3. **多线程异步上传（核心工程规范）**：
   * **绝对不能在主线程/渲染线程发送网络请求！** 必须创建一个独立的**网络发送线程（Worker Thread）**或使用 Qt 的异步槽机制。
   * 将待上传的数据推入一个“网络任务队列”，由后台线程慢慢发送给服务器。即使网络延迟高达几秒甚至断网，前台看病画面依然要保持丝滑流畅。

### 🎯 交付目标

* 在客户端点击“一键上传”，界面提示“正在后台同步...”，同时医生可以继续流畅地操作内窥镜。几秒后提示“同步成功”，登录服务器或查看数据库，能看到新增的病历行以及刚刚上传的牙齿红框截图。

---

## 📅 阶段七：性能飞跃与全栈联调（系统打磨与查找功能）
**目标：** 进行全链路压力测试，确保系统在商业级、临床级场景下的高可用性与数据回溯能力。

### 🛠️ 核心任务
1. **多线程架构全解耦**：
   * 最终系统梳理为四大线程协同作战：**线程 A（视频采集）**、**线程 B（AI 推理）**、**线程 C（UI 渲染）**、**线程 D（云端异步网络上传）**。
2. **异常与断网处理**：
   * 编写 C++ 容错逻辑：若网络连接失败，将数据暂存到本地 SQLite 数据库中，标记为“未同步”；当检测到网络恢复时，自动触发后台批量重试上传。
3. **数据历史查找回溯**：
   * 在 Qt 界面上开发一个“历史病历”看板，输入患者姓名，通过 `GET` 请求向服务器索要历史列表，点击某条记录即可远程加载并显示当年的 AI 诊断红框截图，方便医生进行前后病情对比。

### 🎯 交付目标
* 端到端延迟控制在 100ms 以内（本地流畅度 30 FPS 以上）。
* 具备极强的抗网络波动能力，全面实现“线下高效看病，线上永久留痕”的数字化医疗闭环。

---

## 💡 全栈升级版避坑指南
1. **数据类型转换避坑**：OpenCV 的 `cv::Mat` 是不能直接发给服务器的。必须先用 `cv::imencode(".jpg", mat, buffer)` 将其转换成内存中的 JPG 字节流，再塞进 HTTP 请求体中。
2. **拒绝阻塞式通信**：再次强调，C++ 的网络请求（如 `cpr::Post`）默认是阻塞的。如果直接写在按钮点击事件里，一旦服务器回应慢，整个软件界面就会“未响应”并卡死，这在医疗器械行业是绝对不允许的交互事故。**必须用异步或多线程！**
